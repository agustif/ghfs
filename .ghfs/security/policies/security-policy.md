## What is a Security Policy?

A security policy tells security researchers and users:
- How to report security vulnerabilities
- What versions are supported
- Expected response time
- Security update process

## Recommended Security Policy Template

Create a `SECURITY.md` file in the repository root with content like:

```markdown
# Security Policy

## Supported Versions

Currently supported versions for security updates:

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We take security vulnerabilities seriously. If you discover a security issue, please report it by:

1. **Do NOT** open a public issue
2. Email security@[domain] with:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if any)

3. You should receive a response within 48 hours
4. We'll work with you to understand and address the issue

## Security Update Process

- Security patches are released as soon as possible
- Critical vulnerabilities: < 7 days
- High severity: < 14 days  
- Medium/Low: next scheduled release

## Disclosure Policy

- Coordinated disclosure: we'll work with you before public announcement
- Credit: we acknowledge security researchers (with permission)
```

## GitHub Private Vulnerability Reporting

Alternatively or additionally, enable Private Vulnerability Reporting in repository settings:
- Go to Settings > Security > Code security and analysis
- Enable "Private vulnerability reporting"
- Researchers can then report issues privately through GitHub
