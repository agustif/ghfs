## Overview

Complete **tabula rasa** rewrite of ghfs using Effect v4 with effect/unstable/cli.

## Architecture

### Domain Layer (src-effect/domain/)
- Schema.Class for Issue, PullRequest, Repo, SyncState
- Schema.TaggedError for all error types
- ExecuteOp union with all operations

### Services Layer (src-effect/services/)
- **GhfsConfig**: Config-based configuration with Redacted secrets
- **GitHubClient**: HttpClient-based GitHub API (retry, rate-limit ready)
- **MirrorFs**: FileSystem service for .ghfs/ management
- **SyncEngine**: Orchestrates issue/PR sync workflow
- **ExecutionEngine**: Parses and executes operations

### CLI Layer (src-effect/cli/)
- @effect/cli (effect/unstable/cli) with Command.make
- Commands: sync, execute, status
- NodeRuntime.runMain entry point

## Principles Followed

✅ Programs as values: Effect<A, E, R>  
✅ Execute at edge only: NodeRuntime.runMain  
✅ Effect.fn / Effect.fnUntraced patterns  
✅ Services extend Context.Service with static layer  
✅ Platform services (FileSystem, HttpClient, Path) instead of raw Node  
✅ Config with Effect Config + Redacted  
✅ Typed errors with Schema.TaggedError  
✅ Layer composition with Layer.provide/mergeAll  

See docs/effect-principles.md for full principles.
